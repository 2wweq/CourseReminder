## 1. 背景与目标
用户是学生，常因忘记课程时间而手忙脚乱。目标：用户在外部将课表照片或教务系统课表整理为约定模板的 Excel，程序导入 `.xlsx`、解析校验并保存到本地；**在程序运行期间**，每节课开始前按可配置提前量（默认 40 分钟）在屏幕右下角弹出**程序自绘的提醒卡片**并播放提示音，避免迟到/缺课。程序本身不承担照片识别，核心功能完全离线。
成功标准：经人工核对确认后的课表 100% 正确；程序运行且在学期内时到点必响，提醒内容含课程名、教室与开始时间。

## 2. 目标用户与角色
| 角色 | 描述 | 典型诉求 |
|---|---|---|
| 学生（本人，单用户本地工具） | 用电脑上课、自习的大学生 | 课前提前被提醒，能直接看到是哪节课、在哪个教室 |

## 3. 业务流程（主流程）
1. 用户在外部将课表照片或教务系统课表整理为约定模板的 `.xlsx`（也可完全在程序内手动录入）。
2. 程序导入 Excel，解析「课程」「节次时间」两张工作表并逐行校验；失败时列出「工作表 第N行 [字段]：原因」，旧课表不动。
3. 用户核对解析结果，点「确认导入」后才原子替换课表并保存到 `data/schedule.json`；点「取消」则旧课表保持。
4. 用户在「设置」页填写学期首周周一（必须是周一）与结束日期并保存——它决定周次/单双周如何计算、以及学期边界内是否提醒。
5. 用户双击 `CourseReminder.exe` 运行；点窗口右上角 X **只最小化到任务栏**（程序不退出，提醒继续）。
6. 程序每分钟扫描一次：对到期的大节在屏幕右下角弹提醒卡片（默认 6 秒消失，鼠标悬停暂停），同课同大节当天只提醒一次；点卡片跳到「今日课表」并列出今日剩余课程。
7. 要真正退出，只有一条路：主窗口「设置」页 →「退出课表提醒」（二次确认后退出）。

## 5. 非功能需求
| 编号 | 类别 | 要求 |
|---|---|---|
| NFR-001 | 隐私 | 课表数据只存本地；Excel 导入、查看和提醒均无需联网 |
| NFR-002 | 可靠 | 提醒触发时刻误差 ≤ 1 分钟（每分钟扫描一次）；未经确认的导入不得驱动提醒 |
| NFR-003 | 低占用 | 常驻后台仅一个一分钟定时器，资源占用小、无感知 |
| NFR-004 | 通知体验 | 提醒必须真正可见（不依赖系统通知开关）：右下角自绘卡片 + 提示音，可从卡片分辨是哪节课、哪个教室 |
| NFR-005 | 独立性 | 不依赖 DSH、浏览器、Office 或教务系统页面常驻；核心功能完全离线运行 |
| NFR-006 | 数据位置 | 全部数据（课表、设置、提醒状态、日志、备份）只存放在程序所在文件夹的 `data/` 内，不写入系统盘用户目录或其他位置；整个文件夹可整体移动/备份 |
| NFR-007 | 健壮性 | 每次保存前备份旧文件（备份失败只记日志不阻断保存）；临时文件落盘后替换，避免断电留下半截文件；未处理异常只弹一次提示并写日志，不静默吞掉 |
| NFR-008 | 运行环境 | Windows 10/11 x64；免安装文件夹版依赖 .NET 8 Desktop Runtime（x64），不要求安装 Office |
| NFR-009 | 单实例 | 重复双击不会开出第二个后台进程：检测到已有实例时激活其主窗口 |

## 6. 约束与假设
- 前提约束（用户明示+已确认）：仅在程序运行时有效；电脑关机、睡眠或程序未运行时错过的提醒一律不补发。
- **不提供开机自启（v0.1.7 用户决定撤销）**：程序不再写注册表启动项，设置页也没有自启开关；需要自启时由用户自行把快捷方式放进「启动」文件夹（`shell:startup`）。
- **不使用系统托盘（v0.1.7 用户决定撤销）**：程序不创建任何托盘图标与右键菜单，所有操作都在主窗口内。
- 通知形态：自绘卡片窗口，不经过 Windows 通知中心，不注册 AppUserModelID。
- 范围（已确认 2026-11-21）：本期仅电脑端；手机推送兜底（Bark/飞书/WxPusher）留二期。
- 平台：用户电脑为 Windows x64。
- 实现形态（2026-11-22 确认）：独立 Windows 桌面小程序（WPF），不做成 DSH 插件，日常运行不依赖 DSH。
- 发布形态（v0.1.7 定稿）：仓库只收录源码与文档；本地 `dotnet publish` 生成 `dist/` 一个**免安装文件夹版**，并以 GitHub Release 附件 `CourseReminder-v0.1.7-win-x64.zip` 分发（`CourseReminder.exe` + `CourseReminder.dll` + `.deps.json` + `.runtimeconfig.json` + `使用说明.md`），运行后自动生成 `data/`。旧的自包含单文件版已删除，避免拿错版本。
- 数据存放（2026-11-22 确认）：绿色便携式，所有数据放在程序所在文件夹下的 `data/` 子目录，严禁写入 C 盘用户目录（如 `%LocalAppData%`、`%AppData%`）或系统盘其他位置。
- 导入方式（2026-11-22 确认）：照片转 Excel 在外部通过 AI 或人工完成；程序只解析约定模板的 `.xlsx`，不内置视觉识别，不配置模型 API。
- 时间轴（2026-11-22）：从 Excel 的「节次时间」工作表导入。当前课表为：第一大节 08:10-09:40、第二大节 10:00-11:30、第三大节 13:30-15:00、第四大节 15:20-16:50、第五大节 17:00-18:30、第六大节 18:40-20:10；换学期随新 Excel 更新。完全手动录入且无任何节次时，程序自动补这一套默认时间。
- 周次（2026-11-22 确认）：支持单双周/周次范围，周次上限 60；规则与学期起止日期在设置页与 Excel 中提供。
- 连堂提醒（2026-11-22 确认）：每个大节各提醒一次，不做合并。
- 通知交互（2026-11-22 确认）：点击卡片查看今日剩余课程（FR-010）。
- 假设：课表按学期有效，学期结束或换课需更新（重新导入或手动修改）。
- 实际课表概况（2026-11-22 从教务系统课表截图识别，原图未随仓库发布）：周一~周五每天 1~3 个大节，周六无课，周日同一门课连第一至第四大节；设计启示见 [`需求澄清记录.md`](需求澄清记录.md)。

## 7. 验收标准
1. 导入符合模板的 `.xlsx`：显示「解析成功：课程 N 条、节次 M 条」及待导入清单，点「确认导入」后生效并写入 `data/schedule.json`；格式错误能定位到工作表与行号、且不覆盖旧课表；点「取消」旧课表不变。
2. 到点（课前按提前量）屏幕右下角弹出提醒卡片并播放提示音，内容含课程名、教室、上课时间；卡片 6 秒自动消失，悬停暂停，点击跳到「今日课表」并列出今日剩余课程。
3. 关闭系统通知或开启专注助手后，卡片照样显示。
4. 点窗口 X 后程序不退出，只是缩到任务栏且提醒继续；只有「设置」页「退出课表提醒」并二次确认才真正退出。
5. 程序不存在开机自启行为：重启电脑后不会自行启动，设置页也没有自启开关；托盘区不出现本程序图标。
6. 修改课表（重新导入或手动增删改）后，下一次提醒按新课表执行。
7. 配置周次规则后，非生效周的课不提醒；学期开始前与结束后不提醒。
8. 同一课程同一大节当天只提醒一次，重启程序后也不重复（`state.json` 去重，记录保留 60 天）。
9. 运行一段时间后检查：C 盘用户目录下没有本程序产生的任何数据文件，全部数据都在程序文件夹的 `data/` 内。
10. 主窗口含 5 个页：本周课表、今日课表、导入课表、设置、关于；关于页显示版本 v0.1.7 与实际数据目录。
11. 打开程序默认看到整周课表：7 天 × 节次数的网格、内容与已导入课表一致、今天这一列有底纹、当前这节有描边，可翻上一周/下一周。
12. 重复双击程序不会出现两个后台进程；第二次双击会把已最小化的窗口切回前台。

## 9. 术语表
| 术语 | 含义 |
|---|---|
| 提醒卡片 | 程序自绘的无边框置顶窗口，出现在屏幕右下角，6 秒后淡出；不进入 Windows 通知中心 |
| 自绘通知 | 不使用系统通知通道、由程序自己绘制的提醒窗口（本程序的提醒形态） |
| AUMID | Windows 应用用户模型 ID，系统通知通道识别来源应用所需；本程序不使用 |
| 大节 | 连续两个小节组成的上课单元（如 01,02 小节 = 第一大节） |
| 连堂 | 同一门课在时间上连续的多个大节（如周日第一至第四大节） |
| 单双周 | 同一时间段隔周轮流上不同课的排课方式 |
| 生效周 | 按周次规则判断某门课本周是否实际上课 |
| 去重键 | 日期 + 课程 ID + 大节，写入 `state.json`，保证同课同大节当天只提醒一次 |
